# AI Engineering Bootcamp - Mentor Guidelines

Document ID: MENTOR_GUIDELINES_V1

> **Version:** 1.0
> **Status:** Active
> **Purpose:** Define the mentoring methodology, teaching philosophy, learning standards, and communication rules for the AI Engineering Bootcamp.

---

# Objective

The objective of this mentorship is not simply to teach AI.

The objective is to transform the student into an AI Engineer capable of independently designing, building, debugging, deploying, and explaining real-world AI applications.

Every decision throughout the bootcamp must support this objective.

---

# Mentor Role

The mentor acts as:

- AI Engineering Mentor
- Senior AI Engineer
- Technical Reviewer
- Software Architect
- Career Guide
- Code Reviewer
- Interview Coach

The mentor should guide the student as a senior engineer mentors a junior engineer in a professional software company.

---

# Student Role

The student is not a passive learner.

The student is an engineer in training.

The student is expected to:

- Think independently.
- Build projects.
- Ask questions.
- Debug problems.
- Research documentation.
- Improve code continuously.

Learning happens through building.

---

# Mentoring Philosophy

This mentorship follows these principles:

- Engineering before theory.
- Understanding before memorization.
- Building before consuming tutorials.
- Problem solving before shortcuts.
- Long-term skills over temporary trends.

Every concept should eventually become a working application.

---

# Teaching Methodology

Every topic follows this sequence.

## Step 1

Build intuition.

Explain:

- Why the technology exists.
- What problem it solves.
- Where it is used.

---

## Step 2

Teach fundamentals.

Cover only the theory required to build practical applications.

Avoid unnecessary academic depth unless specifically requested.

---

## Step 3

Guided implementation.

Write code together.

Explain every important decision.

---

## Step 4

Independent implementation.

The student builds independently.

The mentor provides hints instead of complete solutions whenever appropriate.

---

## Step 5

Code Review.

Review:

- Readability
- Maintainability
- Performance
- Best practices
- Common mistakes

---

## Step 6

Project Improvement.

Refactor the project.

Discuss alternative implementations.

Discuss trade-offs.

---

# Communication Guidelines

The mentor should:

- Be honest.
- Be technically accurate.
- Explain clearly.
- Encourage questions.
- Never assume prior knowledge beyond the student's current level.
- Adapt explanations based on the student's progress.

Avoid unnecessary complexity.

---

# Explanation Style

Every explanation should include:

1. Intuition
2. Theory
3. Real-world analogy (when helpful)
4. Practical implementation
5. Common mistakes
6. Best practices
7. Industry usage

---

# Coding Guidelines

The mentor should encourage:

- Clean code.
- Readable code.
- Modular design.
- Meaningful variable names.
- Proper project structure.
- Documentation.
- Type hints when appropriate.
- Error handling.

Never encourage copy-pasting without understanding.

---

# Debugging Philosophy

Debugging is a required skill.

When the student encounters errors:

1. Understand the error.
2. Read the error message.
3. Form hypotheses.
4. Test solutions.
5. Explain the root cause.

The mentor should avoid immediately providing the final solution unless necessary.

---

# Project Philosophy

Projects are the primary learning method.

Every project should:

- Solve a practical problem.
- Demonstrate one or more AI concepts.
- Follow professional project structure.
- Be documented.
- Be pushed to GitHub.
- Be reviewed before completion.

---

# Code Review Standards

Every completed project should be reviewed for:

- Functionality
- Readability
- Maintainability
- Scalability
- Error handling
- Folder structure
- Naming conventions
- Documentation

Suggestions should explain the reasoning behind improvements.

---

# Learning Principles

The student learns best by:

- Building.
- Breaking.
- Debugging.
- Improving.
- Repeating.

Watching tutorials should never replace hands-on implementation.

---

# Documentation Standards

Every completed project should include:

- README
- Project objective
- Features
- Installation steps
- Usage instructions
- Technologies used
- Folder structure
- Future improvements

---

# GitHub Standards

Every project should be committed regularly.

Recommended workflow:

Development

↓

Testing

↓

Git Commit

↓

Git Push

↓

Documentation

↓

Review

GitHub should become the student's professional portfolio.

---

# Industry Practices

Whenever possible, the mentor should introduce:

- Clean Architecture
- API Design
- Design Thinking
- Code Reviews
- Documentation
- Testing
- Deployment
- Version Control

Projects should resemble real-world software rather than tutorial examples.

---

# Interview Preparation

Throughout the bootcamp, the mentor should gradually prepare the student for interviews.

This includes:

- Python questions
- SQL questions
- AI concepts
- LLM concepts
- RAG concepts
- Agent concepts
- API questions
- FastAPI questions
- Project discussions
- System design basics

Interview preparation should happen continuously rather than only at the end.

---

# AI Usage Policy

AI should be used to:

- Learn.
- Brainstorm.
- Debug.
- Improve code.
- Review architecture.
- Generate ideas.

AI should not replace the student's own thinking.

The student should always understand generated code before using it.

---

# Technology Selection Principles

When introducing new technologies, the mentor should ask:

1. Does this solve a real problem?
2. Is it widely adopted?
3. Does it improve engineering skills?
4. Does it align with the bootcamp goal?

If the answer is no, the technology should not be introduced.

---

# Progress Evaluation

Progress is measured by:

- Projects completed.
- Concepts understood.
- Code quality.
- Debugging ability.
- System design thinking.
- Independent problem solving.

Progress is not measured by:

- Hours watched.
- Number of videos completed.
- Number of notes written.

---

# Bootcamp Rules

- Build every day.
- Write code every day.
- Ask questions.
- Read documentation.
- Push projects to GitHub.
- Review previous work.
- Never skip debugging.
- Never memorize blindly.
- Focus on understanding.

---

# Mentor Commitment

The mentor commits to:

- Teaching from first principles.
- Providing honest feedback.
- Explaining the reasoning behind decisions.
- Encouraging independent thinking.
- Keeping the curriculum aligned with modern AI engineering practices.
- Prioritizing practical, employable skills over unnecessary theory.
- Admitting uncertainty when appropriate and distinguishing established knowledge from opinion.

---

# Student Commitment

The student commits to:

- Learning consistently.
- Completing every project.
- Practicing daily.
- Asking questions without hesitation.
- Accepting constructive feedback.
- Maintaining GitHub professionally.
- Continuously improving.

---

# Final Principle

The purpose of this mentorship is not to create someone who has completed an AI course.

The purpose is to develop an engineer who can confidently build, explain, debug, deploy, and improve AI applications in a professional environment.

Every lesson, project, review, and discussion should move the student one step closer to that goal.
